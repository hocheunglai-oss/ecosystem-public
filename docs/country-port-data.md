# Country and port data

The landing page keeps Recently viewed above the inline Information extractor. Add location, Country Index and Port Index share the toolbar. Search matches country, port and optional area paths; areas are grouping labels with no index or detail page. Recently viewed shows names without type suffixes. Each port requires a valid country; optional areas must belong to that country.

Hong Kong, Singapore and Gibraltar have one visible port profile each. These are explicit country plus UN/LOCODE aliases (HKHKG, SGSIN and GIGIB), never an inference from how many ports are currently stored. Country entries are omitted from the index/search and old recent links resolve to the port. Their country relationships and independent storage keys remain intact: the profile combines matching tabs, keeps country-only tabs, and routes entry edits and history to the original owner. No documents or audit snapshots are moved or overwritten. Ambiguous duplicate codes do not activate an alias.

Country profiles begin with Suppliers, Refineries, Grades and delivery modes, Tax and regulations, Trader's Remarks, and Uploaded Documents. Port profiles add Port Information first and Price History. The tabs are wrapping buttons, with no horizontal tab scroller. Manage Tabs adds, renames, removes and restores tabs, including defaults. The saved layout has a version marker so reloads and later information edits never regenerate deleted defaults. Stable semantic roles keep renamed Port Information, Uploaded Documents, Refineries and Price History functioning. New tabs with similar names remain ordinary information tabs unless explicitly restored as a default.

Manage Tabs saves changes to a combined country/port profile atomically while retaining each source's independent content, version and audit history. Removing a tab requires confirmation with its entry count; deleted information remains in its historical snapshots. Restoring a tab within an unsaved draft recovers its original content. Restoring a previously deleted default adds an empty tab with its original function. At least one tab remains in the visible profile, while a hidden secondary source may be empty. Tab order can change within each source group. Existing blocks and custom sections survive migration. Port names show a live local clock using port-specific IANA zones (including daylight saving), or an explicitly recorded UTC offset. Countries have no clock; unknown port time zones display a dash.

Text entries, document links, tables, individual table rows and Key Info fields expose editor and update time through compact history icons, accessible by keyboard or touch. Entries without recorded attribution omit the icon. Publication assigns these values from the selected actor and publication time; unchanged entries retain their prior attribution. Older entries recover attribution from an applicable historical change where possible. Moving a section or upgrading the layout does not manufacture an edit.

The compact location workspace shows the workspace title and record name once. The location search, record controls, wrapping tabs and information toolbar stay fixed while only the content below scrolls. Parent country/area links share the record heading, and a Back icon returns to the landing page. Update sits beside History. Information blocks have individual borders and modest spacing. The editor uses an entry outline and a single focused detail pane. Text remains plain text, tables remain structured rows/cells with stable IDs, and file links retain their URLs. Table controls act on the focused row/column, allow movement and width changes, and accept pasted spreadsheet cells. The Reason and Source inputs are removed from the information editor; it still records an automatic change description and preserves existing provenance. The green Feedback for ecosystem button shows +1 beside the theme control. Key Info's Update button omits the reward badge.

These records and their history retain the existing demo persistence model: browser local storage, not shared server-backed audit records. The information extraction API still requires the existing FCUNO/SPC sign-in; development browser tests intercept that API without sending data externally.

## Future port imports

Use official UN/LOCODE as the external location identity, storing the two-letter country code separately from the three-character location code while preserving an internal immutable ID. UN/LOCODE includes non-port locations: import maritime function `1`, retain source release/provenance, review duplicate or changed codes, and update existing records by code rather than name. Facilities/terminals can later belong to a location without pretending each has a separate UN/LOCODE. Country grouping must remain independent of the three explicit profile aliases. This change does not import the worldwide dataset or claim that a country has only one physical port. References: [UNECE Recommendation 16](https://unlocode.unece.org/recommendation16/) and [data attributes](https://unlocode.unece.org/docs/data-attributes/).
