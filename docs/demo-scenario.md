# Isolated test scenarios

## Access and separation

Fictional commercial data belongs only to the explicit TEST DATA mode available to the privately configured active owner administrator. Default to LIVE on startup. Ordinary accounts and other administrators must not gain TEST access by changing browser state. VIEW AS remains read-only.

Separate every test persistence mechanism by owner, mode and generation, or block it in TEST. Do not publish shared records, send outbound messages, call live extraction or import legacy prototype data into LIVE. Public test fixtures contain invented records, never staff provisioning, private customer/financial records or source-report content.

Reset Demo controls and browser reset operations are retired. Reloading is not a reset. Owner-requested cleanup is a separate reviewed operator procedure with private recovery evidence; do not reintroduce a reset button or overwrite a user's data to refresh examples.

## Scenario coverage

Synthetic fixtures may exercise known and unknown buyer/port matches, ambiguous ownership, insufficient credit, suspended buyers, overdue payment, split grades/suppliers and onboarding. Preserve unresolved source text for review. Test enquiries use the same parser and workflow validation while staying inside the isolated test namespace.

Buyer/credit development remains administrator-only; non-administrators see the ECO 2.0 construction gate. Examples may exercise P1 total permanent limits and URGENT expiring overages, but neither fictional values nor prototype approvals establish live credit authority. See [buyer profiles](buyer-profile.md) for calculation and storage boundaries.

Country, port and profile fixtures use titled synthetic text/tables. Private profile tabs must still obey the real authenticated owner boundary; browser-local prototype remarks are a different storage mechanism. No UI-only demo identity selector grants access.

## Verification

Verify LIVE as the default, owner-only TEST entry, owner/mode/generation isolation, account changes, reload, VIEW AS and rejection of shared/outbound mutations. Browser tests intercept service calls and use isolated contexts. Never pass production credentials to public CI or leave automation contexts open.

Theme changes and window resizing preserve work. Shared publication uses contribution eligibility rules; private changes, layout-only changes and synthetic rewards must not create a live contribution. Historical Gold/transport state remains compatibility evidence only and must not restore retired controls.
