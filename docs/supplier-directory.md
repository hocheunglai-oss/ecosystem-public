# Supplier directory

Supplier Profiles opens a centered name-only table directly. SPC VIEW switches to the compact Singapore comparison; there are no Supplier Profiles subcategories or separate Singapore entry/page. The table and profile use the shared supplier API and the same canonical ECO UUID. The recorded legal name and exact SPC short name remain distinct; a profile displays the full legal name once and the short name separately. Legacy SPC IDs resolve to that canonical record through an explicit mapping. Names, aliases and similar brands never establish a company merge by themselves.

`shared/suppliers.ts` defines the contract. `src/lib/supplierApi.ts` loads authenticated lists/details, creates records with request UUID protection, and performs revision-checked updates and archive operations. `src/SupplierWorkspace.tsx` renders the single directory; `src/SharedSupplierProfile.tsx` renders its profile. Global search uses shared supplier summaries. A failed request shows an error/retry state, with no fictional or browser-local supplier fallback.

Search, port, grade and PIC filters are applied by the server before pagination. SPC VIEW uses short names, compact rows, aligned coloured grades, red non-30 terms, quick PIC contribution and BDN/contact/barge/fixture quick views. Only active SPC traders are selectable for new Singapore PIC assignments. Existing ineligible assignments remain visible but cannot be selected for a new assignment. Singapore port SUPPLIERS opens SPC VIEW; other mapped ports show their own normal directory. Registration checks the canonical country/port pair. Unmapped custom ports never fall back to the global directory. The page sizes are 25, 50 and 100, with 50 as the default. Delivery coverage does not establish country of incorporation. No source aggregate creates live fixture records.

The default profile tabs are Supplier Information, Contacts, Barge Fleet and Sources. Key Info includes the FO and GO BDN fields; there is no separate BDN tab. Contacts use compact name/phone rows grouped as Sales and Operation, with retained general operational contacts where applicable. MPA/Infospectrum addresses and contact fields are excluded from the current contact/background presentation and new source enrichment. Older imported evidence remains preserved internally. The retired SPC database is not displayed as a source.

Only real active ECO administrators or SPC traders may add, edit or remove Singapore supplier records, including names, background, operational fields, contacts and barges. Active members may manage non-Singapore supplier records. VIEW AS remains read-only and TEST cannot publish shared changes. The API and database recheck the stored supplier country and authority. Removing a supplier archives its current listing without deleting its identity, reports or historical revisions. Request UUIDs and revisions protect retries and concurrent changes; errors retain unsaved drafts. Changed operational contact/barge records receive server attribution.

Legal-name verification is distinct from source availability: `verified` means the recorded evidence supports the name, while `needs-review` retains the supplied identity without inventing registry verification. A browser change to the legal name requires renewed review. Immutable source evidence is separate from editable company background; dated company facts and source references retain their provenance.

Supplier shared and owner-private tabs use `shared/profileTabs.ts` and the authenticated profile-tabs API. Shared tab permissions follow the supplier country: administrators/SPC traders for Singapore, active members for other ports; ordinary active members can manage their own private tabs. Private ownership comes from the live session, including against other administrators, and private tabs disappear during VIEW AS. Their titles/content do not enter shared search, history, exports or contribution counts. Shared/private collections have independent revisions and exact-payload retry protection. Tab management supports rename, add, remove and reorder with insertion indicators. See [Profile data access and recovery](profile-data-access.md) for scope rules, archival recovery and the remaining browser-local country/port/buyer master-data boundary.

The interface follows the shared country/port design tokens and ordinary control styles. Resizing preserves work. Original Infospectrum PDFs can be published through the controlled operator workflow into ECO's private report storage; profiles expose authenticated, short-lived download links when a stored report is available. This is separate from general supplier uploads: browser-only supplier uploads, links, folders and move destinations remain blocked until general shared attachment storage is implemented. Publication and recovery procedures remain in the private operator records. Successful supplier changes award one contribution through the existing audited operation; replaying the same request does not award another. Curated 50–100 word INFOSPECTRUM SUMMARY facts appear below Key Info with dated main-report provenance; operator enrichment does not fabricate user contributions.

The previous demonstration directory, browser-local supplier knowledge tabs, browser-only supplier edits and source-derived fixture projections are historical prototype behavior, not the current shared supplier persistence contract. Existing browser data is not silently promoted. No buyer/company identity link, credit authority or migrated fixture history is inferred by this release.
